# 素材库与视频分析自动匹配方案

编制日期：2026-10-15

范围说明：本文按“素材库基于现有视频分析结果，支持自动选材和裂变”理解需求。现有库结构依据 `media-library-schema-review.zh.md` 中 2026-10-13 的只读检查记录，本次没有重新连接线上数据库。下文新增字段、表、接口和能力均为设计建议，不代表已经开发或部署；不执行任何数据库变更。

## 1. 目标

本方案用于将现有视频分析结果接入线上素材库，实现以下流程：

```text
原视频分析
→ 识别镜头和字幕时间
→ 判断镜头用途与可替换性
→ 查询线上素材库片段
→ 按硬条件和语义匹配排序
→ 校验替换后的时长、画面和上下文
→ 生成一组或多组替换方案
→ 自动创建剪映草稿或基础预览
```

第一版重点支持“原视频裂变”和“脚本分镜自动选材”，不要求一次实现完整的视频编辑器。

## 2. 现有数据的定位

当前素材库可以继续使用，不建议重建已有表：

| 数据表 | 当前职责 | 在自动匹配中的职责 |
|---|---|---|
| `myh_assets` | 素材文件、地址、哈希、类型、状态、宽高、时长 | 获取素材和做基础硬过滤 |
| `myh_media_analysis` | 整条素材的摘要、对象、人物、产品、动作、风格、向量 | 整条素材召回和候选排序 |
| `myh_media_temporal_features` | 分镜区间、运动、亮度、颜色、首尾帧特征 | 片段级检索、时长裁剪和衔接校验 |

现有表适合保存分析结果，但不能只依赖整条素材的摘要。自动替换必须以“片段”为最小检索单位。

已有素材分析完整且版本兼容时直接复用，仅补缺失字段；不要重新上传和分析全部素材。历史规划中的早期工程状态不能替代当前代码验收。

## 3. 兼容原则

1. 保留现有 `myh_assets`、`myh_media_analysis`、`myh_media_temporal_features`。
2. 线上库继续保存素材和分析结果，本地 SQLite 只保存任务、候选方案、去重记录和草稿映射。
3. 现有 `/analyze_video`、`/analyze_video_tasks` 等分析接口保持兼容。
4. 新增字段优先使用可空字段，避免影响旧素材和旧分析记录。
5. 未分析、低置信度和明确识别为“没有”的状态必须区分。
6. 不把业务规则永久压缩成单个 `replaceable=true/false`，而是保存用途、限制和证据。
7. 所有时间统一使用整数微秒，并采用半开区间 `[start_us, end_us)`。

## 4. 素材入库流程

### 4.1 登记素材

上传或同步素材时，先写入 `myh_assets`：

- `asset_id`
- 原始文件名和存储地址
- 文件哈希
- 媒体类型
- 宽、高、帧率、总时长
- 音频和视频轨道信息
- 所属租户、项目、素材目录
- 授权范围和失效时间
- `active/disabled/deleted` 状态

文件哈希用于避免重复分析；素材地址需要经过可访问性检查，不能只记录一个线上 URL。

### 4.2 生成基础代理

为长视频生成低码率代理、封面和波形。代理用于分析和网页预览，原文件用于最终裁剪或创建草稿。

建议保存：

- `proxy_url`
- `thumbnail_url`
- `waveform_url`
- 代理分辨率、编码和生成版本
- 原文件与代理的校验和

### 4.3 执行分析

素材分析建议分为四层：

1. **媒体层**：时长、帧率、画幅、音轨、清晰度、黑帧和异常帧。
2. **镜头层**：镜头边界、景别、机位、运镜、转场、运动强度。
3. **语义层**：人物、产品、场景、动作、情绪、用途和内容摘要。
4. **文字与语音层**：字幕、花字、水印、口播、旁白和时间戳。

这些结果写入线上分析表；若当前表没有对应列，建议通过 JSON 扩展字段或新增关联表补充，不要覆盖已有摘要。

| `scene_category` | 场景类别 |
| `usage_roles` | 用途标签，可多选 |
| `subjects` | 人物、商品、物体 |
| `actions` | 动作标签 |

| `lighting` / `color_style` | 光线和色彩风格 |

| `speech_type` | 口播、对话、旁白、环境声或未知 |
| `has_subtitles` | 是否有硬字幕 |
| `has_overlay_text` | 是否有花字或包装文字 |

| `product_ids` | 商品或 SKU 标识 |
| `quality_score` | 清晰度、抖动、曝光等综合分 |
| `confidence` | 分析置信度 |
| `embedding` | 片段语义向量 |
| `embedding_model` / `embedding_version` | 向量来源 |

### 5.2 用途标签建议

上表是标准化业务字段，不是直接执行的建表清单。数据库已有 `shot_start_us`、`shot_end_us` 时映射到业务层的 `start_us`、`end_us`，不再增加同义列；已有主键可直接作为 `clip_id`。`duration_us` 在这里明确指可用区间长度，避免和原文件时长混淆。

产品包装文字、硬字幕、花字应分别标记，不能因为包装有文字就排除正常产品素材。布尔属性允许未知值；模型没有给出证据时，不得默认为 `false`。

用途标签不要只设置一个枚举，可以使用多标签：

| 标签 | 默认替换策略 |
|---|---|
| `product_empty_scene` 产品空境 | 默认可替换 |
| `pain_point` 痛点画面 | 有条件可替换 |
| `motion` 运动或过程画面 | 有条件可替换 |
| `intro` 片头/开场画面 | 有条件可替换 |
| `product_detail` 产品细节 | 需要同 SKU 或人工确认 |
| `proof` 证据、效果、对比 | 默认锁定 |
| `cta` 价格、购买、行动号召 | 默认锁定 |
| `oral_delivery` 人物口播 | 默认不可替换 |
| `dialogue` 对话或口型同步 | 默认不可替换 |
| `unknown` 未知 | 必须人工复核 |

“有语音”不等于“口播”。应结合人物口型、说话主体和分镜用途判断。

## 6. 原视频分镜的匹配输入

原视频分析完成后，每个分镜形成一个标准化匹配请求：

```json
{
  "scene_id": "scene-004",
  "start_us": 7200000,
  "end_us": 9600000,
  "duration_us": 2400000,
  "usage_role": "product_empty_scene",
  "content_summary": "桌面上的产品静物展示",
  "required_scene": ["室内", "桌面"],
  "required_actions": ["静止展示"],
  "product_id": "sku-001",
  "aspect_ratio": "9:16",
  "has_speech": false,
  "replace_policy": "replaceable",
  "previous_scene_id": "scene-003",
  "next_scene_id": "scene-005"
}
```

匹配输入必须保留原始分析证据和置信度，不能只传一段自然语言描述。

## 7. 自动匹配规则

### 7.1 第一层：硬条件过滤

以下条件不满足时直接排除：

- 素材状态不是可用。
- 租户、项目或授权范围不匹配。
- 商品/SKU 不符合要求。
- 片段可用时长不足。
- 画幅或分辨率不满足最低要求。
- 含有禁止的水印、硬字幕或敏感内容。
- 片段被标记为口播、证据或 CTA，且当前镜头要求可替换。
- 分析版本失败或已失效。

### 7.2 第二层：结构化排序

候选按以下维度排序：

```text
用途匹配
+ 商品匹配
+ 场景匹配
+ 动作匹配
+ 时长余量
+ 画幅和分辨率
+ 画面质量
+ 前后镜头风格衔接
```

建议先从数据库筛选出 20～50 个候选，再读取向量和首尾特征排序，不要每次扫描全库向量。

### 7.3 第三层：语义模型复核

对排名靠前的 3～5 个候选调用多模态模型，判断：

- 是否真的符合分镜用途。
- 是否出现错误人物、错误商品或错误动作。
- 替换后是否破坏上下文。
- 是否需要裁剪、变速或调整入点。
- 是否存在明显违和、跳轴、动作断裂或风格冲突。

模型只能提出建议，硬条件和不可替换规则优先于模型自由发挥。

用途匹配采用兼容关系，而非简单要求候选自身 `replaceable=true`。例如替换原片头时，候选可以是合适的产品特写，不要求素材自身也是片头。来源镜头的替换许可与候选素材的内容用途必须分开判断。

## 8. 自动裁剪和边界处理

1. 优先选择时长足够且动作完整的片段。
2. 候选片段源入点不固定为 0，允许在长视频中选择中间区间。
3. 源区间和时间线区间分开保存。
4. 裁剪边界按视频帧时间戳复核，微秒字段用于业务精度，最终切割必须落在有效帧边界。
5. 检查首帧、尾帧与相邻镜头，避免黑帧、上一镜残留和动作突然截断。
6. 口播和口型同步镜头默认禁止变速。
7. 非口播镜头可配置轻微变速，但必须记录速度和音画影响。
8. 候选不足时返回缺镜原因，不使用不合格素材硬凑。

### 8.1 音频与字幕

第一版保留原视频音轨和锁定镜头，只替换选定区间的画面，并将替换素材原声静音，避免双重音轨。原声中的动作音效仍需与新画面复核。

沿用分析结果中的逐镜转写和时间戳，只在替换区间添加字幕；未替换部分不新增字幕，也不改变其原有硬字幕。转写属于语音识别，不等同于恢复原片字幕的字体、位置和文字内容。无可信转写时返回字幕缺失，不凭画面推断台词。OCR 不重新加入默认分析链路。

## 9. 50 组裂变方案

### 9.1 组合生成

对每个可替换分镜先生成候选池，再进行组合搜索：

```text
候选池
→ 排除同片段和重叠区间
→ 应用素材复用策略
→ 计算整片连贯性
→ 计算重复度和差异度
→ 生成方案
→ 校验总时长、字幕、音频和草稿结构
```

### 9.2 去重策略

系统应明确是哪一种去重：

1. **组合不重复**：不同方案的片段组合不能完全相同。
2. **片段不复用**：不同方案不能使用相同或重叠的源片段。
3. **原素材不复用**：不同方案不能来自同一原素材。

推荐默认采用“组合不重复 + 关键镜头片段不重叠”。如果要求 4 个镜头全部使用不同片段，50 组至少需要 200 个合格片段。

### 9.3 相似度指标

建议分别记录：

- 原画面保留率。
- 片段重复率。
- 结构相似度。
- 语义相似度。
- 音频保留率。
- 商品和 CTA 保留率。

这些指标用于内部排序和审核，不应直接宣称可以保证平台相似度低于某个固定百分比。

## 10. 本地数据库记录

线上素材库只读，以下数据保存到本地 SQLite：

### `material_match_jobs`

- 匹配任务 ID
- 原分析任务 ID
- 项目/租户 ID
- 目标方案数量
- 当前状态、阶段、错误和耗时
- 创建时间、完成时间

### `material_match_candidates`

- 匹配任务 ID
- 原分镜 ID
- 候选 `asset_id`、`clip_id`
- 匹配分数
- 排除原因
- 模型复核结果

### `material_variant_plans`

- 方案 ID、批次 ID
- 每个分镜使用的素材片段
- 源入点、源出点、时间线起止点
- 选择理由和随机种子
- 相似度指标
- 草稿 ID、预览地址和导出地址

这样可以在不修改线上素材库的情况下实现任务重试、方案对比和素材使用去重。

任务请求保存幂等键、策略版本和模型配置快照（不含密钥）；素材使用预留与方案写入应在事务中完成，防止并发任务选中同一禁止复用的片段。严格去重需明确作用范围是当前批次、项目还是跨批次。若多个服务实例各用独立 SQLite，不能保证全局去重，届时应将使用记录交给一个共享业务库管理。

## 11. 建议接口

接口名称可根据现有路由风格调整，建议新增：

| 接口 | 用途 |
|---|---|
| `POST /material_match_tasks` | 根据分析任务创建匹配任务 |
| `GET /material_match_tasks/{task_id}` | 查询匹配状态和阶段耗时 |
| `GET /material_match_tasks/{task_id}/candidates` | 查看每个分镜候选素材 |
| `POST /material_match_tasks/{task_id}/variants` | 生成多组裂变方案 |
| `GET /material_match_tasks/{task_id}/variants` | 查询方案、相似度和草稿 |
| `POST /material_match_tasks/{task_id}/draft` | 将选定方案创建为一个完整草稿 |
| `POST /material_match_tasks/{task_id}/validate` | 执行替换后的画面和边界校验 |

上述路径拟放在现有 `/openapi/capcut-mate/v1` 前缀下。生成方案、创建草稿和校验这些耗时操作均提交后台子任务并返回任务 ID，不能在 HTTP 请求内等待全部完成。默认由后端自动选择候选，候选列表仅用于排查，不要求前端再次逐镜选择。

原有视频分析接口只负责产生分析结果，不强制自动访问素材库，避免增加原分析任务的耗时和失败面。

## 12. 线上数据库连接方案

推荐采用“线上只读素材库 + 本地任务库”：

```text
分析服务
  ├─ 线上 MySQL：素材、分析、片段、授权信息
  └─ 本地 SQLite：任务、候选、方案、草稿映射、日志
```

要求：

- 使用独立的只读数据库账号。
- 查询必须带租户、状态和分析版本条件。
- 数据库连接超时和重试不能阻塞主分析任务。
- 选中素材后生成短期签名地址或下载到本地临时目录。
- 草稿创建前验证素材地址可被 Windows Worker 访问。
- 线上库不可用时，原视频分析仍可完成，但匹配任务应明确标记为等待或失败。

继续通过项目根目录 `env.db.dev` 配置连接，不把凭据写进代码、日志或文档。素材查询与模型目录查询使用不同的仓储对象；若共用同一数据库配置，也不要混用业务表和任务表。

## 12.1 开发目录与复用边界

以下为后续开发位置规划，本次不创建业务文件：

| 位置 | 建议职责 |
|---|---|
| `src/service/video_analysis/material_matching/` | 新增独立子模块，集中放只读素材查询、字段映射、过滤排序、组合分配和任务编排 |
| `src/schemas/` 下独立匹配 schema 文件 | 请求、候选、方案和状态的数据契约 |
| `src/router/` 下独立匹配路由文件 | 新接口注册，不修改原剪映接口参数 |
| `tests/` | 字段映射、硬约束、并发预留、裁剪、重启恢复和草稿回归 |
| `docs/` | 接口说明、素材字段约定和验收报告 |

复用现有 `video_analysis` 内的模型配置、视频模型客户端、正式切割流程、草稿构建和替换服务，不复制一套模型密钥解密或临时切割实现。实际复用前需核对函数契约和测试，不能仅因模块名称相同便认为可以直接调用。

不修改 `src/pyJianYingDraft/` 框架源码。每组方案生成一个包含所有分镜的完整草稿，保留原草稿，避免多个方案并发修改同一草稿。草稿地址、分镜视频地址、整片可播放预览地址分别返回；草稿创建成功不等于已经渲染完整 MP4。

## 12.2 索引、模型和观测

- 按实际硬过滤查询设计组合索引，并在测试库用执行计划验证；先过滤状态、有效版本、权限、用途、商品和时长，再做候选排序。
- 多用途标签若成为高频查询条件，新增小型标签关联表；不要为每个 JSON 属性机械增加索引。
- 向量需要匹配模型、版本、维度和归一化方式。当前没有兼容向量时，可先用分类、标签和摘要排序，不能混用不同来源向量。
- 文本匹配和视频复核分别选择具备相应能力的线上模型 ID；视频复核必须传入实际候选片段，只有文字摘要时注明“文本复核”，不能声称已检查画面。
- 模型并发按供应商限额配置，上传与模型请求分别限流；429、超时有限重试，达到预算或截止时间后明确结束。
- 分别记录数据库查询、召回、排序、模型上传、模型推理、下载、裁剪、质量校验、组合分配、草稿构建耗时，以及候选数量、淘汰原因和重试次数。
- 不默认重新执行原视频的全局报告、OCR 或全部素材转写。直接消费已完成的分镜分析和字幕，对选中候选才下载与加工。

## 13. 实施阶段

### 阶段一：只读接入

- 接入 `myh_assets`、`myh_media_analysis`、`myh_media_temporal_features`。
- 统一字段映射、分析版本和时间单位。
- 实现硬条件过滤和候选列表。
- 不创建草稿，不改变原分析流程。

### 阶段二：片段语义补全

- 补充分镜用途、商品、动作、文字和口播字段。
- 增加有效区间和置信度。
- 对旧素材执行增量补分析。
- 建立缺字段和低置信度报告。

### 阶段三：模型复核和自动裁剪

- 对少量候选执行多模态复核。
- 支持长视频中间区间选择。
- 增加边界复核、时长校验和上下文检查。
- 记录每次匹配的理由和模型版本。

### 阶段四：多方案和草稿

- 增加方案组合、去重和容量计算。
- 自动裁剪并创建完整草稿。
- 返回每个分镜的素材、时间区间、预览地址和相似度指标。
- 支持失败重试和任务恢复。

## 14. 验收标准

- 选定商品和用途后，不返回授权或 SKU 不符合的素材。
- 口播、证据和 CTA 默认不会被自动替换。
- 候选片段的时间区间不越界，且可实际下载和播放。
- 替换片段时长满足原分镜要求，首尾无黑帧和上一镜残留。
- 候选不足时明确返回缺镜原因。
- 50 组方案不出现完全相同的组合。
- 每组方案都能追溯到素材、片段、分析版本和选择理由。
- 生成草稿失败不会污染原分析任务和线上素材库。

## 15. 推荐结论

现有素材库可以作为第一版基础，但开发重点不是简单增加一个“素材分类字段”，而是将整条素材分析结果落实为可检索的片段索引，并把用途、商品、授权、可替换限制和边界信息结构化保存。

推荐先实现“只读查询 + 硬条件筛选 + 候选列表”，用真实素材验证字段覆盖率；确认候选质量后，再接入模型复核、自动裁剪、50 组裂变和剪映草稿生成。这样不会影响现有分析接口，也能避免模型错误直接生成不可用草稿。
