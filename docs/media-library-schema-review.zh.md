# 线上素材库表结构检查与优化方案

检查日期：2026 年 10 月 13 日

检查范围：`myh_media_analysis`、`myh_media_temporal_features`，以及关联素材主表 `myh_assets`。

检查方式：只读查询表结构、索引、记录数量和少量样例。未修改线上数据。本文不包含数据库地址、账号或密码。

## 一、结论

现有数据结构方向符合视频自动替换需求，可以沿用，不需要重建素材库。

但目前还不足以直接支撑“自动匹配素材、裁剪、生成 50 组替换方案”。主要缺口是：

1. 素材基础信息尚未完整填充。
2. 分镜表缺少片段级语义和用途分类。
3. 商品身份、文字类型、有效区间等筛选条件不充分。
4. 需要明确有效分析版本和素材使用去重策略。

核心问题不只是缺少索引，而是“片段级语义”和“已有字段实际填充”不足。

## 二、现有结构可以复用的部分

| 表 | 已有数据 | 可承担的用途 |
| --- | --- | --- |
| `myh_assets` | 文件位置、访问地址、分类、文件哈希、宽高、时长、状态 | 获取素材、基础筛选、文件去重 |
| `myh_media_analysis` | 内容摘要、分类、对象、动作、人物、产品、摄影属性、质量分、语义向量 | 整条素材的内容检索和排序 |
| `myh_media_temporal_features` | 分镜起止微秒、镜号、运动强度、亮度、颜色直方图、首尾帧向量 | 定位可用片段、辅助评估视觉衔接 |

现有 `asset_id`、`analysis_id` 和 `analysis_version` 可以关联素材、分析结果和分镜，适合作为后续开发基础。

### 已有索引和约束

- 分析表：`asset_id + analysis_version` 唯一约束、`task_id` 唯一约束、分析状态索引、更新时间索引。
- 分镜表：`analysis_id + shot_index` 唯一约束、`asset_id + shot_start_us` 索引。
- 素材主表：分类、素材类型、状态、上传人、创建时间、MD5、名称等索引。
- 分析表和分镜表已有素材关联外键。

这些索引主要服务于任务管理和素材关联，尚未针对自动选材查询设计。

## 三、实际样本检查结果

检查时的数据情况：

- 未删除的视频素材：1 条。
- 成功分析：1 条。
- 失败分析：1 条。
- 分镜记录：1 条。

成功样本是产品展示视频，分镜区间为 `0–4,800,000` 微秒，即 0–4.8 秒。

样本数量较少，当前不能验证批量检索性能或生成 50 组方案的效果。

| 发现的问题 | 对自动替换的影响 |
| --- | --- |
| 素材主表的 `width`、`height`、`duration` 为空 | 无法可靠筛选横竖屏、时长和分辨率 |
| 摘要描述缓慢移动，但 `camera_motion` 为空 | 结构化检索会漏掉实际存在的镜头运动 |
| 景别、机位、光线、色彩等多项为空 | 无法充分判断替换后的风格一致性 |
| 只有整条素材语义，没有逐镜语义 | 无法判断多镜头素材中某个区间具体展示什么 |
| `has_text=1` 未区分文字类型 | 产品包装文字可能被误当作字幕排除 |
| 有商品类目，但没有明确商品身份字段 | 可能将不同品牌、不同商品错误匹配 |
| 有文件位置和访问地址，但未验证本地访问 | 数据库可连接，不代表素材文件可下载 |

样本整条语义向量和首尾帧向量均有 1024 维数据。需要明确各自的生成输入、模型和用途，不能仅因维度一致就混用。

检查到的分镜样本没有发现 `asset_id` 与关联分析记录不一致，或结束时间小于等于开始时间的情况；这不等于已经验证视频实际切口。

## 四、建议补充的最小字段

优先扩展现有分析表，不急于引入新的数据库。以下均为建议，尚未执行表结构变更。

| 建议位置 | 字段 | 用途 |
| --- | --- | --- |
| 分镜表 | `content_summary`、`scene_category`、`actions` | 描述当前区间，而不是整条视频 |
| 分镜表 | `usage_roles` | 标注产品空境、痛点、运动、片头、口播，允许多标签 |
| 分镜表 | `product_id`、`brand_id` | 限制商品身份；未知时明确为空 |
| 分镜表 | `has_speech`、`has_subtitles`、`has_overlay_text`、`has_watermark` | 区分语音、字幕、花字和水印 |
| 分镜表 | `usable_start_us`、`usable_end_us` | 保存排除转场、黑帧等之后的可用区间 |
| 分镜表 | `camera_type`、`camera_motion`、`lighting`、`color_style` | 匹配景别、镜头运动、光线和画面风格 |
| 分镜表 | `semantic_embedding` 及对应模型、版本信息 | 检索该分镜的内容 |
| 分析表或分镜表 | `confidence`、`missing_fields` | 区分“没有该内容”和“没有识别出来” |

### 规则边界

“口播不可替换”由本地替换策略决定。素材库保存是否口播等内容属性，不建议把所有业务规则永久压缩成一个 `replaceable=true/false`。

`has_speech` 仅表示有语音，不等同于口播。口播用途需要结合人物讲话画面和内容语义判断。

商品身份应由明确识别或业务绑定提供，不应仅根据“药品包装盒”等宽泛类别推断成某个具体商品。

### 时间边界

微秒字段可以继续使用，统一约定为半开区间：

```text
[start_us, end_us)
```

实际切割仍需要映射到视频帧时间戳。存成微秒不代表切口天然准确，也不能单靠该字段保证没有相邻镜头残留。

有效区间应满足：

```text
shot_start_us <= usable_start_us < usable_end_us <= shot_end_us
```

## 五、索引与分析版本优化

### 1. 统一分类

先建立用途和分类的标准值或映射，避免“产品展示”“商品展示”“产品空境”等名称各自使用，却无法统一检索。

类别与用途应区分：内容属于产品展示，不意味着一定适合所有产品空境位置。

### 2. 明确有效分析版本

每个素材应明确采用哪条已经完成且有效的分析结果。

不能直接选择最大 `id`，否则可能选到失败记录，或混用不同版本的分析与分镜。

匹配时应通过选定的 `analysis_id` 关联分镜，避免仅按 `asset_id` 关联后混入历史版本。

### 3. 按查询设计索引

建议结合实际查询评估以下方向：

- 分析状态与分类筛选。
- 商品身份与镜头用途筛选。
- 素材状态、类型及分类筛选。
- 可用时长筛选。

具体组合索引应在查询和字段设计确定后，用执行计划验证，不宜提前把所有组合都建索引。

多标签用途需要高频筛选时，可增加小型标签关联表，无需把所有 JSON 字段拆表。

### 4. 向量排序

第一版先通过结构化条件缩小候选，再读取少量候选向量进行排序，不要每次拉取全库向量。

内容检索向量与首尾衔接向量分开使用，并校验模型、维度和生成方式是否兼容。

## 六、本地与线上职责划分

| 位置 | 保存的数据 |
| --- | --- |
| 线上素材库 | 素材信息、分析结果、片段区间、分类和可用状态 |
| 本地 SQLite | 视频分析任务、匹配方案、素材使用记录、草稿映射 |
| 文件存储 | 原素材、预览文件及必要的派生文件 |

本地只读查询线上素材库，选定素材后再获取文件，不需要提前把全部素材视频下载到本地。

素材授权、账号归属和访问权限如由其他表管理，应在接入时关联确认。本次未审查完整权限体系。

## 七、自动匹配流程

```text
读取原视频分镜分析
→ 排除口播等不可替换分镜
→ 选择有效素材分析版本
→ 按商品、用途、画幅、状态、时长等条件筛选
→ 根据片段语义和视觉属性排序
→ AI 复核少量候选及前后镜头衔接
→ 分配不同素材组合
→ 获取选中素材并裁剪
→ 创建草稿和预览
```

候选不足时返回原因，不自动放宽商品身份、授权或其他必要约束。

## 八、50 组替换方案的去重

建议将每次方案选择记录在本地，不修改线上分析结果。

片段使用记录至少包含：

- 批次和方案标识。
- 原视频分镜标识。
- 素材 `asset_id`。
- 分镜或片段标识及分析版本。
- 实际裁剪起止区间。
- 对应草稿片段标识。

需要区分三种要求：

1. 组合不重复：允许素材复用，但整组组合不同。
2. 片段不复用：不同方案不能重复使用相同或重叠片段。
3. 原素材不复用：同一原素材的不同区间也不能跨方案使用。

仅按完全相同的起止时间去重不足以排除高度重叠片段，必要时需计算区间重叠。

例如每条成片替换 4 个位置、生成 50 条，若要求所有位置都使用不同片段，需要分配 200 个不重复片段。是否允许来自同一原素材，需要单独确定。

内容匹配度与成片相似度应分别评估，不能将检索分数解释为平台判定的视频相似度，也不承诺平台判断低于某个固定百分比。

## 九、推荐实施顺序

### 第一阶段：补全数据

- 填充素材宽高、时长等基础信息。
- 核查摄影属性为空的原因，修复分析输出到字段的落库链路。
- 明确未知值、空值和明确不存在的区别。
- 验证本地能获取选定素材文件。

### 第二阶段：补充分镜语义

- 增加片段内容描述和用途分类。
- 增加商品身份、文字类型及有效区间。
- 明确有效分析版本与分镜关联。

### 第三阶段：只读匹配

- 接入线上只读查询。
- 实现硬条件筛选和候选排序。
- 对少量候选进行 AI 衔接复核。
- 根据真实查询增加必要索引。

### 第四阶段：多组分配与草稿

- 实现批次级素材使用记录和去重。
- 自动选择裁剪区间。
- 创建多组草稿并返回预览。
- 在足够规模的素材样本上测试候选覆盖率和匹配效果。

## 十、安全与验证边界

- 数据库配置文件 `env.db.dev` 在检查时未命中 Git 忽略规则，建议加入忽略，避免误提交凭据。
- 本次只做结构和少量样本检查，没有修改线上表、索引或数据。
- 尚未验证素材文件下载、批量检索性能、AI 候选复核效果或完整 50 组方案生成。
- 当前成功样本只有一个镜头，整条摘要暂时可以辅助使用；多镜头素材需要逐镜描述才能准确挑选中间片段。
